# APEX OTT

Discord 자판기로 OTT 상품을 판매하고, **관리자가 구매 로그를 확인해 DM으로 직접 전달**하는 구조의 스토어 봇입니다.
결제(포인트 차감)는 즉시 이루어지고, 상품 지급은 관리자가 **ID·PW / KEY / 기타** 중 원하는 형식으로 입력해 보냅니다.

```
사용자 자판기 구매
      │  포인트 차감 · 재고 차감 · 주문번호 생성
      ▼
구매 로그 채널 (지급 버튼 · 취소 버튼)
      │  관리자가 [상품 지급] → 방식 선택 → 입력
      ▼
구매자 DM  ── 이미지 카드 + 클릭 복사 코드블록 + 메시지
      │
      └─ 30분이 지나도 지급되지 않으면  DM의 [티켓 열기] 활성화 → 문의 채널 생성
```

## 주요 기능

| 기능 | 설명 |
|---|---|
| 자판기 패널 | 카테고리 선택 메뉴 + **제품 · 충전 · 정보** 버튼(이모지) + 배너 이미지. 상품을 나열하지 않고 선택 시에만 표시 |
| 구매 | 포인트 차감과 동시에 재고 차감, 주문번호(`OTT-YYMMDD-0001`) 발급 |
| 구매 로그 | 지정 채널에 **구매 완료** 카드 게시. 상품 지급 / 주문 취소 버튼 포함 |
| 지급 | ID·PW, KEY, 기타(링크·안내문) + 선택 메시지 입력 |
| DM 전달 | 지급 시 **이미지 카드**와 **클릭하면 복사되는 코드블록**을 함께 전송 |
| 후기 | 지급 완료 DM의 **[후기 남기기]** → 별점(1~5) + 후기 작성 → 후기 채널에 게시 |
| 30분 제한 | 제한 시간 초과 시 구매자에게 지연 안내 DM, [티켓 열기] 사용 가능 |
| 티켓 | 주문 정보가 포함된 문의 채널 자동 생성, 관리자만 닫기 가능 |
| 취소 | 지급 대기 주문 취소 시 포인트·재고 자동 복구 |
| 재전송 | DM 차단 등으로 전송 실패 시 `/재전송` 또는 대시보드에서 재시도 |
| 충전 | 토스 입금 알림 웹훅으로 자동 충전 + 수동 승인 |
| 대시보드 | 주문 지급, 상품/재고, 유저 포인트, 후기, 충전, **채널·역할 선택**, 패널 설치/배너 설정 |
| 이미지 | 구매 영수증 카드와 전달 카드 자동 생성(Pillow + Pretendard) |

> 쿠키 검사기, 쿠키 판매, 랭킹/출석, Render 배포 설정은 모두 제거되었습니다.

## 설치

### 1) 요구 사항

- Python **3.12** 권장 (3.11 이상)
- Discord 봇 토큰
- 봇 권한: `Send Messages`, `Embed Links`, `Attach Files`, `Read Message History`, `Manage Channels`(티켓)

### 2) 패키지 설치

```bash
pip install -r requirements.txt
```

### 3) 환경변수

`.env.example` 을 복사해 `.env` 로 저장합니다.

```env
DISCORD_TOKEN=봇_토큰
SECRET_KEY=임의의_긴_문자열
ADMIN_IDS=관리자_디스코드_ID
GUILD_ID=서버_ID
ADMIN_PASSWORD=대시보드_관리자_비밀번호
```

- `ADMIN_IDS` 를 비워도 **서버 관리자 권한**이 있으면 명령어를 사용할 수 있습니다.
- `GUILD_ID` 를 넣으면 슬래시 명령어가 해당 서버에 즉시 등록됩니다.
- `ADMIN_PASSWORD` 를 비우면 최초 실행 시 **랜덤 비밀번호가 생성되어 콘솔 로그에 출력**됩니다.

### 4) 실행

```bash
python main.py
```

- Discord 봇과 웹 대시보드가 함께 실행됩니다.
- 대시보드: `http://localhost:5000`
- 초기 비밀번호: `.env`의 `ADMIN_PASSWORD` (비우면 실행 로그에 생성된 비밀번호 출력) → 로그인 후 **설정 → 보안**에서 변경하세요.

## 최초 설정

1. 봇을 서버에 초대하고 `python main.py` 실행
2. 대시보드 로그인 → **설정** 탭
   - 구매 로그 채널
   - 충전 로그 채널
   - 티켓 카테고리
   - 후기 채널
   - 공지 채널, 티켓 알림 역할(선택)
   - 전달 제한 시간(기본 30분)
   - 입금 계좌
3. **자판기 패널** 카드에서 패널을 설치할 채널과 배너 이미지 URL을 지정 → **패널 설치 / 새로고침**
4. 자판기를 설치할 채널에서 `/자판기` 로도 패널을 설치할 수 있습니다.

> 채널·카테고리·역할은 대시보드에서 **Discord 목록에서 직접 선택**합니다. 목록에 없는 채널은 **ID 직접 입력** 칸에 숫자 ID를 넣으면 됩니다. 채널을 자동으로 만들지 않습니다.

## 판매 흐름 자세히

### 구매

- 자판기에서 카테고리 → 상품 → **구매하기**를 누르면 즉시 결제됩니다.
- 포인트가 부족하면 현재 잔액과 함께 안내됩니다.
- 결제 후 구매자 DM으로 **주문 접수 카드**가 전송됩니다.

### 자판기 패널

- **Components V2 컨테이너**로 만들어져 **하나의 카드 안에** 제목·설명·카테고리 선택·제품/충전/정보 버튼·배너 이미지가 함께 표시됩니다.
- 상품 상세, 주문 로그, 구매/지급 DM, 티켓, 후기, 충전, 취소 확인 등 **버튼이 있는 모든 메시지도 V2 카드 안에** 배치됩니다.
- 게시 후에도 대시보드/`/패널설치`로 새로고침할 수 있습니다.
- 배너 이미지는 대시보드 **설정 → 자판기 패널** 또는 `/패널배너` 로 변경합니다.

### 재고 무제한

- 상품 재고를 `-1` 로 설정하면 **무제한**입니다.
- 대시보드 상품 수정에서 **재고 무제한** 체크박스를 사용하세요.
- 무제한 상품은 구매해도 재고가 줄지 않고 품절되지 않습니다.

### 지급 (관리자)

구매 로그의 **[상품 지급]** 버튼을 누르면 세 가지 방식을 선택할 수 있습니다.

| 방식 | 입력 | DM 표시 |
|---|---|---|
| ID · PW | 아이디, 비밀번호, 메시지(선택) | 이미지 카드 + 아이디/비밀번호 코드블록 |
| KEY | 키/코드, 메시지(선택) | 이미지 카드 + KEY 코드블록 |
| 기타 | 전달 내용(링크·안내문), 메시지(선택) | 이미지 카드 + 전달 내용 |

- DM에는 **이미지 카드**와 텍스트 코드블록이 함께 전송됩니다.
- 코드블록을 클릭(모바일은 길게 누르기)하면 값이 그대로 복사됩니다.
- 구매 로그는 **지급 완료** 상태로 자동 갱신되고 버튼이 사라집니다.
- 대시보드 **개요 / 주문** 탭에서도 동일하게 지급할 수 있습니다.

### 30분 경과 · 티켓

- 주문 접수 DM의 **[티켓 열기]** 버튼은 제한 시간(기본 30분)이 지나야 동작합니다.
- 시간이 지나면 봇이 구매자에게 **지연 안내 DM**을 한 번 더 보냅니다.
- 티켓을 열면 주문 정보가 포함된 비공개 채널이 생성되고, 관리자 역할을 멘션합니다.
- 관리자만 **[티켓 닫기]** 로 종료할 수 있습니다.

### 취소 · 재전송

- 지급 대기 주문은 **[주문 취소]** 로 취소할 수 있으며 포인트와 재고가 복구됩니다.
- DM 전송에 실패한 주문은 `/재전송 주문번호` 또는 대시보드 **재전송** 버튼으로 다시 보냅니다.

### 후기

- 상품 지급 완료 DM에 **[후기 남기기]** 버튼이 함께 전송됩니다.
- 별점(1~5)을 선택하고 후기 내용을 작성하면 **후기 채널**에 게시됩니다.
- 주문 1건당 1개의 후기만 작성할 수 있습니다.
- 대시보드 **후기** 탭에서 전체 후기와 평균 별점을 확인할 수 있습니다.

## 포인트 충전 (토스 알림)

1. 사용자가 자판기 **[포인트 충전]** → 충전 신청(입금자명·금액)
2. 안내된 계좌로 입금
3. 폰 Tasker가 토스 알림을 웹훅으로 전송
4. 입금자명과 금액이 일치하면 자동 충전 + DM 안내

Tasker 설정:

```
POST  https://내주소/api/deposit-webhook?key=웹훅키
Content-Type: application/json

{"title":"%antitle","body":"%antext"}
```

- 웹훅 URL과 키는 대시보드 **설정 → 입금 자동 감지**에서 확인/재발급할 수 있습니다.
- 자동 매칭이 실패한 입금은 충전 로그 채널에 **미매칭 입금**으로 표시됩니다.
- 대시보드 **충전** 탭에서 수동 승인도 가능합니다.

## Render 수동 배포 (Blueprint / render.yaml 사용 안 함)

Render 대시보드에서 **New → Web Service** 로 직접 만들면 됩니다. 저장소에 `render.yaml` 은 없습니다.

### 1) 서비스 설정

| 항목 | 값 |
|---|---|
| Repository | `kongjoonll-bit/Apex-OTT` |
| Language / Runtime | `Python 3` |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `python main.py` |
| Health Check Path | `/ping` |
| Instance | **1개만** (봇 + 웹이 한 프로세스) |

### 2) 환경변수

| Key | Value |
|---|---|
| `DISCORD_TOKEN` | 봇 토큰 |
| `SECRET_KEY` | 긴 랜덤 문자열 (`openssl rand -hex 32`) |
| `ADMIN_PASSWORD` | 대시보드 관리자 비밀번호 |
| `ADMIN_IDS` | 관리자 디스코드 ID (쉼표 구분) |
| `GUILD_ID` | 명령어를 등록할 서버 ID |
| `PUBLIC_URL` | `https://<서비스명>.onrender.com` |
| `COOKIE_SECURE` | `true` |
| `PYTHON_VERSION` | `3.12.10` (선택, `.python-version` 도 포함됨) |

### 3) DB 영구 저장 (중요)

Render 무료 플랜은 **디스크가 휘발성**이라 재배포·재시작 시 SQLite DB 가 초기화됩니다.

- **유료 Persistent Disk** 를 추가하고 마운트 경로를 `/var/data` 로 지정하세요.
- 환경변수 `APEX_DB_PATH=/var/data/apex_ott.db` 를 추가합니다.
- 디스크가 없으면 서버가 재시작될 때마다 유저 포인트·주문·설정이 사라집니다.
- 배포 전 기존 DB 는 대시보드 **설정 → DB 파일 다운로드** 또는 `/db보내기` 로 백업하세요.

### 4) 무료 플랜 슬립 주의

- 무료 Web Service 는 15분간 요청이 없으면 슬립되어 **봇이 오프라인**이 됩니다.
- 외부 업타임 모니터(cron-job.org 등)에서 `https://<서비스명>.onrender.com/ping` 을 **5분마다** 호출하면 슬립을 줄일 수 있습니다.
- 24시간 안정 운영에는 Starter 이상 플랜을 권장합니다.

### 5) 배포 후

1. Render 로그에서 `[APEX OTT] 초기 관리자 비밀번호` 또는 봇 로그인 확인
2. `https://<서비스명>.onrender.com` 로그인 → **설정** 탭에서 채널 ID 입력
3. `/패널설치 채널:#구매하기` 로 자판기 패널 설치
4. 슬래시 명령어가 안 보이면 Discord 에서 `Ctrl + R`
